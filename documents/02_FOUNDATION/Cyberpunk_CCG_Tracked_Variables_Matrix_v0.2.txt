CYBERPUNK CCG — TRACKED VARIABLES MATRIX v0.2
Plain-text design matrix
Created: 2026-04-23
Updated: 2026-04-23 — persistent card entities, zone-change model, banish rule

============================================================
0. PURPOSE
============================================================

This file lists the game-state variables that should be tracked by the engine
and how those variables may be used for card design.

A variable should not become a mechanic just because it exists. It must be:

    visible enough,
    actionable enough,
    distinct enough,
    and fun enough.

Legend:

    Visibility:
        PUBLIC       Both players can see it.
        OWNER        Owner can see it.
        HIDDEN       Engine knows it, players may not.
        PARTIAL      Some information is visible.

    Safety:
        HIGH         Safe to use heavily.
        MEDIUM       Use with caution.
        RISKY        Use lightly or save for later.
        DEFER        Track maybe, but do not build around yet.

    Launch Use:
        FULL         Supports a full launch archetype.
        PACKAGE      Use as a small support package.
        TECH         Use as counter/tech only.
        FUTURE       Track but save for later.


============================================================
0A. PERSISTENT ENTITY / ZONE-CHANGE RULE
============================================================

Cards are persistent entities.

Destroy, discard, banish, draw, play, return, and move are zone changes.

The engine should not delete card instances when they are destroyed, discarded,
or banished. It should update current_zone and append a zone-change record.

Core zone meanings:

    Destroy:
        board/lane -> destroyed_pile

    Discard:
        hand -> discard_pile

    Banish:
        any legal source zone -> banish_pile

Hard banish rule:

    Cards in the banish pile may be counted or inspected by history, but no
    card design should ever move a card out of the banish pile.

Required generic zone-change record:

    card_instance_id
    base_card_id
    owner_player_id
    controller_player_id
    from_zone
    to_zone
    from_lane
    to_lane
    caused_by_player_id
    caused_by_card_id
    turn_number
    phase
    cost_at_change
    power_at_change
    text_at_change
    tags_at_change
    was_created
    was_modified
    zone_change_reason

Allowed card design:
    Count banished cards.
    Trigger when banished.
    Care that a card was banished this game.

Forbidden card design:
    Move a card out of the banish pile.
    Return a banished card to hand.
    Return a banished card to deck.
    Return a banished card to board.
    Copy a banished card as a recovery workaround.

Design rule:
    Banish is persistent in the engine but final in gameplay.
