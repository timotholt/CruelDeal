# cardgame_implementation_plan_02.txt
PLAN_VERSION: 1.1.0
TARGET_SPEC: cardgamespec_01.txt (SPEC_VERSION: 1.3.0)

============================================================
PURPOSE
============================================================

This document defines a STRICT, STEP-BY-STEP IMPLEMENTATION PLAN
for LLMs to build the 3-lane card game defined in cardgamespec_01.txt.

Rules for any LLM following this plan:

- Do NOT skip steps.
- Do NOT merge steps unless explicitly allowed.
- After each step, run at least one simple, measurable test.
- Only move to the next step if tests pass.
- If a step depends on a broken earlier step, FIX THE EARLIER STEP FIRST.

React is MANDATORY for the UI layer and will be introduced in
a dedicated phase after the core engine logic is stable.

A database layer MUST be defined conceptually as interfaces
(e.g. repositories) but does NOT need a real DB implementation
in this plan.

This plan has 34 steps.

============================================================
PHASE 0 – PROJECT & TOOLING SETUP (Steps 1–4)
============================================================

STEP 1 – Create Project Skeleton
--------------------------------
Goal:
- Create a minimal TypeScript + React project structure.

Required top-level structure:
- package.json
- tsconfig.json
- src/
  - engine/ (core game logic)
  - ui/ (React components)
  - shared/ (types, constants)
- test/ or __tests__/ (for unit tests)
- public/ (if using CRA/Vite)

Tests:
- Run `npm test` (or equivalent) with a dummy test.
- Run `npm run dev` or `npm start` to verify the dev server launches,
  even if the UI just shows "Hello".

------------------------------------------------------------
STEP 2 – Install Dependencies
-----------------------------
Goal:

Required:
- React + ReactDOM
- TypeScript + ts-node (if needed)

Disallowed at this stage:
- No DB drivers (Postgres, Mongo, etc.).
- No heavy UI libraries yet (MUI, Tailwind) unless absolutely needed.

Tests:

STEP 12 – Implement createCardInstance
--------------------------------------
Goal:
- Implement function:
  createCardInstance(def: CardDefinition, owner: "p1" | "p2", createdInZone: Zone, createdBy?: CreatedBy): CardInstance

Behavior:
- baseCost/currentCost = def.baseCost
- basePower/currentPower = def.basePower
- baseText/currentText = def.baseText
- startedInDeck = (createdInZone === "DECK")
- created = !startedInDeck
- createdInZone = createdInZone
- zone = createdInZone or adjusted if needed

Tests:
- Unit test: deck-created vs hand-created instance behave as expected for startedInDeck/created flags.

STEP 17 – Implement Internal Collection Helpers

STEP 18 – Implement DestroyCard
-------------------------------
Goal:
- DestroyCard(instanceId):
  - If on BOARD:
    - Remove from lane slot (set slot to null).
  - Set zone="DESTROYED".
  - Push into destroyedPiles[owner].

Tests:
- Start with card on BOARD.
- DestroyCard.
- Assert lane slot null + card in destroyedPiles[owner].

------------------------------------------------------------
STEP 19 – Implement DiscardCard
-------------------------------
Goal:
- DiscardCard(instanceId):
  - HAND → DISCARDED
  - Move card from hands[owner] to discardPiles[owner].
  - zone="DISCARDED".

Tests:
- Put a card in hands.p1.
- DiscardCard.
- Assert correctly moved and zone updated.

------------------------------------------------------------
STEP 20 – Implement BanishCard
------------------------------
Goal:
- BanishCard(instanceId):
  - From any zone, remove card from the relevant collection.
  - zone="BANISHED".
  - Push into banishedPiles[owner].
  - If from BOARD, clear slot.

Tests:
- Test from BOARD, HAND, DESTROYED.
- Assert card only appears in banishedPiles and nowhere else.

------------------------------------------------------------
STEP 21 – Implement MoveCard
----------------------------
Goal:
- MoveCard(instanceId, targetLane, targetSlot):
  - Only valid from BOARD.
  - Validate lane in [0..2] and slot in [0..3].
  - Choose rule if target slot occupied (prefer disallow/NO-OP at first).

Tests:
- Move from lane 0, slot 0 to lane 2, slot 3.
- Assert old slot null, new slot points to card.

Tests:

Goal:

STEP 25 – Implement Priority Calculation
----------------------------------------
Goal:
- Implement updatePriority(gameState):
  - Compare total board power.
  - Ties → "p1".

Tests:
- Two scenarios:
  - p1 > p2 → priority "p1"
  - p2 > p1 → priority "p2"
  - equal → "p1"

------------------------------------------------------------
STEP 26 – Implement Lane Outcome Function
-----------------------------------------
Goal:
- Implement:
  - computeLaneOutcome(gameState, laneIndex): "p1" | "p2" | "tie"

Behavior:
- Use calculateLanePower for both players for that lane.
- Compare and return result.

Tests:
- Several scenarios:
  - p1 > p2 → "p1"
  - p2 > p1 → "p2"
  - equal → "tie"

------------------------------------------------------------
STEP 27 – Implement Match Outcome Function (WINNER LOGIC)
----------------------------------------------------------
Goal:
- Implement:
  - computeMatchOutcome(gameState): "p1" | "p2" | "draw"

Behavior:
1. For lanes 0, 1, 2:
   - Get laneResult = computeLaneOutcome(gameState, laneIndex).
2. Count lane wins:
   - lanesWonP1, lanesWonP2.
3. If lanesWonP1 > lanesWonP2 → "p1".
4. If lanesWonP2 > lanesWonP1 → "p2".
5. If equal:
   - Option A (simple): return "draw".
   - Option B (optional tie-breaker): compare total board power and decide.
   - Whatever rule is chosen MUST be documented and consistent.

THIS STEP DEFINES WHERE THE END-OF-GAME WINNER IS DETERMINED.

Tests:
- Scenario where p1 wins 2 lanes → "p1".
- Scenario where p2 wins 2 lanes → "p2".
- Scenario with 1–1 and one tied lane → "draw" (unless tie-breaker chosen).

------------------------------------------------------------
STEP 28 – Integrate Winner Logic Into runEndOfGame
--------------------------------------------------
Goal:
- Implement runEndOfGame(gameState) that:
  1. Resolves EndOfGame abilities.
  2. Calls computeMatchOutcome(gameState).
  3. Returns an object:
     {
       outcome: "p1" | "p2" | "draw",
       laneResults: ["p1"|"p2"|"tie", ...],
       finalGameState: GameState
     }

Tests:
- Small integration test: invoke runEndOfGame on a pre-configured state
  and assert outcome matches expectations.

PHASE 6 – FULL TURN RUNNER & REACT WIREFRAME (Steps 33–34)
============================================================

STEP 33 – Implement playTurn() and Basic React UI
-------------------------------------------------
Goal:
- Implement:
  - playTurn(gameState, p1Plays, p2Plays) that:
    1. Calls runStartOfTurn.
    2. Applies plays (using playCard logic).
    3. Calls runRevealPhase.
    4. Calls runEndOfTurn.
  - A minimal React UI in src/ui:
    - Shows:
      - Current turn and energy.
      - Lanes with slots.
      - Cards in hand.
    - Provides:
      - A way to click a card and a lane to "queue" a play.
      - A button to "Resolve Turn" that calls playTurn.

Tests:
- Manual: run dev server, click around, ensure no runtime errors.
- Automated: shallow test that App renders without crashing.

STEP 34 – Define Conceptual Database Interfaces
-----------------------------------------------
Goal:

Examples:
- interface GameRepository {
    saveGame(state: GameState): Promise<void>;
    loadGame(id: string): Promise<GameState | null>;
  }

- interface DeckRepository {
    getDeckForPlayer(playerId: string): Promise<CardDefinition[]>;
  }

Implementation:
- Provide in-memory stub implementations:
  - InMemoryGameRepository
  - InMemoryDeckRepository

Tests:
- Save a GameState and load it back.
- Confirm equality.

============================================================
END OF IMPLEMENTATION PLAN
============================================================

Summary of where the winner is determined:
- The winner computation is implemented in STEP 27 via computeMatchOutcome(gameState),
  and integrated into runEndOfGame(gameState) in STEP 28.
- These functions constitute the canonical “who won the game?” logic and MUST be used
  by both engine code and React UI to display results.
